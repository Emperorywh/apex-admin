# 用户组织关系处理规则 — SPEC 14.3

本文档记录用户离职/禁用时的组织关系处理规则，作为 SPEC 14.3 的配套文档。

## 适用范围

- 模块：`org`（组织架构）
- SPEC 条款：14.3 "用户离职或禁用时组织关系按规则处理"
- 关联模块：`identity`（用户管理）

## 组织关系数据模型

### 用户-部门关系（`org_user_departments`）

- 用户具有**明确的主部门**（`is_primary=True`）。
- 基座默认**仅支持主部门**——每个用户只能关联一个部门。
- 兼职部门（多部门关联）由业务配置决定，**本基座不提前实现**此扩展点。
- 数据库唯一约束 `(user_id)` 保证一个用户仅一个主部门。
- `user_id` 跨模块引用 identity 模块用户 ID，不做数据库外键（SPEC 5.5）。
- `department_id` 为同模块外键（`org_departments`），使用 `ondelete=RESTRICT`。

### 用户-岗位关系（`org_user_posts`）

- 一个用户可被分配**多个岗位**。
- 数据库唯一约束 `(user_id, post_id)` 保证分配**幂等且防重复**。
- `user_id` 跨模块引用 identity 模块用户 ID，不做数据库外键（SPEC 5.5）。
- `post_id` 为同模块外键（`org_posts`），使用 `ondelete=RESTRICT`。
- **岗位不直接替代角色和权限**（SPEC 14.2）。岗位仅为组织管理维度，
  与 RBAC 模块的角色/权限完全独立。

## 离职/禁用时的组织关系处理规则

### 规则

当用户被**禁用**（`POST /users/{id}/disable`）时：

1. identity 模块发布 `USER.DISABLED` 事务内领域事件。
2. org 模块注册的事务内事件处理器
   `ClearUserOrgRelationsOnDisabled`（处理器编码：
   `ORG.CLEAR_USER_ORG_ON_DISABLED`）在**同一事务内**执行：
   - 删除该用户在 `org_user_departments` 中的主部门关系。
   - 删除该用户在 `org_user_posts` 中的全部岗位关系。
3. 此操作与用户禁用和会话吊销**同提交、同回滚**（SPEC 5.7）。
4. 如果组织关系清除失败，整个用户禁用操作回滚。

### 语义说明

- **组织关系清除后不可恢复**——用户重新启用后需重新设置组织关系
  （主部门和岗位分配）。
- **审计记录不受影响**——审计日志是不可变的（SPEC 18.2），历史记录
  仍保留用户曾经的组织关系变更记录。
- **权限不发生隐式变化**——用户被禁用后，其 RBAC 角色和权限本身
  不变，但用户因处于 `disabled` 状态无法通过认证（SPEC 12.3），
  实际无法使用任何权限。组织关系的清除不影响 RBAC 权限模型
  （SPEC 14.3: "部门变更不会隐式扩大用户权限"，SPEC 14.2:
  "岗位不直接替代角色和权限"）。

## 部门变更不扩权原则（SPEC 14.3）

SPEC 14.3: "部门变更不会隐式扩大用户权限"。

本基座中：

1. **部门不影响权限**：用户的 RBAC 权限完全由 `rbac` 模块的角色分配
   决定（SPEC 13.1/13.2），与用户所属部门无关。
2. **岗位不影响权限**：岗位是组织管理维度，不参与权限决策
   （SPEC 14.2: "岗位不直接替代角色和权限"）。
3. **数据权限（EXT）不实现**：基座不实现基于部门的数据权限控制
   （非建设目标）。如果未来业务项目需要数据权限，应作为 EXT 扩展
   独立实现，不影响 G1-G4 核心验收。

因此，部门变更（用户换部门、部门层级调整、部门禁用等）不会引起
用户 RBAC 权限的任何变化。权限变更只能通过 RBAC 模块的角色分配/
移除操作显式触发。

## 事件处理器注册

事件处理器通过 `ModuleDefinition` 显式注册（SPEC 5.7）：

| 处理器编码 | 事件编码 | 动作 |
|---|---|---|
| `ORG.CLEAR_USER_ORG_ON_DISABLED` | `USER.DISABLED` | 清除用户全部组织关系 |

处理器在 Composition Root（identity Router 的 `get_user_use_case` 依赖注入函数）
中与 auth 模块的事件处理器一起注入到 `UserUseCase` 的事件分发器中。
