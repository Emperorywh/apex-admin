# 架构决策记录（ADR）

本目录记录项目中具有持久影响的技术与架构决策。

## 目的

SPEC 29.2 要求"架构决策记录关键取舍及其原因"。
每一份 ADR 记录一个决策的上下文、权衡与结论，使后续维护者能够理解决策
背后的动机，并在需要变更时有据可依。

## 何时需要新增 ADR

- 升级固定技术栈的主版本或替换核心组件（SPEC 5.4）。
- 引入跨模块数据库外键（SPEC 5.5）。
- 变更安全相关参数（如 Argon2id 参数，SPEC 12.x）。
- 跨站部署等偏离默认安全模型的决定。
- 任何对未来开发具有约束力的架构取舍。

## 命名约定

`ADR-NNNN-kebab-case-title.md`

- `NNNN`：四位顺序编号，从 `0001` 开始。
- 标题使用小写英文和连字符，便于检索。

## 模板

```markdown
# ADR-NNNN：标题

- **状态**：proposed | accepted | superseded by ADR-NNNN
- **日期**：YYYY-MM-DD

## 背景

描述决策的上下文、面临的约束和需要解决的问题。

## 决策

清晰陈述选择的方案。

## 理由

说明为什么选择此方案，以及排除了哪些替代方案。

## 影响

该决策带来的后果和约束。
```
